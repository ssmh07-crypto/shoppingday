# Shoppingday 네이버쇼핑 순위 관측 확장 프로그램

성장상품관리에서 사용자가 요청할 때 실제 Chrome 탭을 열어 네이버쇼핑 가격비교 PC
자연검색 결과를 최대 100위까지 확인한다. 예약 조회, CAPTCHA 해결, IP 변경 또는 차단
우회 기능은 포함하지 않는다.

## 로컬 설치

1. Chrome에서 `chrome://extensions`를 연다.
2. 오른쪽 위 `개발자 모드`를 켠다.
3. `압축해제된 확장 프로그램을 로드합니다`를 누른다.
4. 저장소의 `chrome-extension` 폴더를 선택한다.
5. Shoppingday 성장상품관리 페이지를 새로고침한다.

코드를 변경한 뒤에는 확장 프로그램 화면에서 새로고침 버튼을 누르고 Shoppingday
페이지도 다시 불러온다.

## 관측 범위

- PC `search.shopping.naver.com`의 기본 검색 결과만 확인한다.
- `광고` 표시가 있는 상품 카드는 순위에서 제외한다.
- 상품 카드 URL과 속성에서 채널 상품번호 또는 스마트스토어 상품 경로를 찾아
  대상 상품을 식별한다.
- 결과에는 PC, 확인 시각, 확인 범위와 발견·미노출·차단·실패 상태를 저장한다.
- 네이버 공식 순위 API 값이 아니라 조회 시점의 공개 화면 관측값이다.

Chrome 확장 프로그램만으로 실제 모바일 Chrome과 동일한 사용자 에이전트·화면을
보장할 수 없으므로 모바일 조회는 이 버전에 포함하지 않는다.

## 직감 위탁상품 품절·단종 확인

성장상품관리 `상품 운영`에서 `zicgam.com/product/detail.html?product_no=...` 형식의
공급처 URL을 입력하면 로그인된 Chrome 탭으로 상품을 연다. 직감은 비로그인 상태에서
승인회원 로그인 페이지로 이동하므로 Chrome에서 먼저 직감 승인 계정으로 로그인해야
한다.

## 직감 전체 상품 가져오기

확장 프로그램 0.5.3부터 Shoppingday의 `위탁상품 가져오기` 화면에서 직감 전체
카탈로그 수집을 시작할 수 있다. 로그인된 직감 탭이 전체상품 목록 페이지를 먼저
순회한 뒤 상품 상세를 한 건씩 확인한다. 상세 결과는 20개씩 압축해 비공개 임시 저장소에
올리고, 수집이 끝나면 GitHub Actions가 DB에 일괄 저장한다. 압축 파일은 Cloudflare
Worker를 통과하지 않고 2시간 유효한 서명 URL로 Supabase Storage에 직접 업로드한다.
신규 상품은 추가하고 기존 상품은 공급처 원본 스냅샷만 갱신한다.

- 목록·상세 수집 중에는 Shoppingday 탭과 직감 작업 탭을 닫지 않는다. 화면에
  `GitHub Actions DB 저장` 단계가 표시된 뒤에는 탭을 닫아도 서버 작업은 계속된다.
- 같은 Shoppingday 탭에서 다른 관리 페이지로 이동해도 저장 작업은 계속된다. 다시
  `위탁상품 가져오기`로 돌아오면 확장 프로그램 세션에 저장된 최신 진행 상태를 복구한다.
  Shoppingday 탭 또는 직감 작업 탭 자체를 닫으면 작업이 중단될 수 있다.
- 상품 수에 따라 수집과 저장에 시간이 걸릴 수 있다. `중단`은 Chrome 수집 단계에서만
  제공하며, GitHub Actions 저장이 시작된 뒤에는 진행률과 실행 로그 링크로 상태를 확인한다.
- 상세 조회가 45초를 넘으면 해당 상품을 실패로 기록하고 다음 상품을 계속 처리한다.
  상세 조회는 1회 재시도하며, 20건 연속 실패하면 최근 3건의 상품번호·단계·오류를 남기고
  전체 수집을 중단한다.
- GitHub Actions는 `product_no`를 기준으로 멱등 저장하고 20개마다 신규·갱신·변경 없음
  진행률을 Shoppingday 화면에 반영한다. 성공하면 임시 수집 파일을 자동 삭제한다.
- 서명 발급 또는 Storage 직접 업로드가 HTTP 429·5xx나 네트워크 오류로 실패하면
  2초·5초·10초·20초 간격으로 자동 재시도한다.
- 최초 Shoppingday 작업 생성이 HTTP 429·5xx나 네트워크 오류로 실패해도 같은 간격으로
  재시도한다. 생성 요청은 대기 중인 작업을 재사용하므로 응답 유실 후에도 중복 작업을
  만들지 않는다.
- HTTP 200이어도 필요한 JSON 필드가 없는 중간 응답은 성공으로 취급하지 않고 재시도한다.
  최종 실패 시에는 응답 형식과 받은 필드 이름만 표시하며 토큰이나 키 값은 노출하지 않는다.
- `product_no`로 중복을 제거하므로 다시 실행해도 같은 상품을 중복 생성하지 않는다.
- 목록 상품 카드 밖의 추천·최근 본 상품 링크는 수집하지 않는다.
- 홈의 `전체상품` 링크 하나를 기준으로 해당 목록의 페이지네이션만 순회한다. 개별
  카테고리를 합산하지 않으며 전체상품 링크를 찾지 못하면 안전하게 중단한다.
- 전체상품 URL의 `page` 값을 1부터 하나씩 올려 직접 요청한다. 상품이 처음 0개로
  확인된 페이지를 종료 표식으로 보고 직전 비어 있지 않은 페이지를 마지막으로 판정한다.
- 비어 있지 않은 페이지에서는 요청 URL의 페이지 번호와 페이지네이션 활성 번호가
  일치해야 한다. 범위를 넘긴 요청을 다른 페이지로 돌려보내거나 기존 상품을 다시
  보여주는 경우는 URL·활성 번호·상품번호 반복 검증으로 실패 처리한다.
- 페이지 간 같은 `product_no`가 반복되면 범위를 넘긴 페이지가 기존 목록을 다시
  보여준 것으로 보고 중단한다.
- 직감이 표시한 전체 상품 수를 읽을 수 있으면 발견 수와 함께 확인창에 보조 정보로
  표시한다. 표시 총수를 읽지 못해도 최초 빈 페이지까지 순차 확인했다면 상세 저장을
  시작할 수 있다.
- 상품 수를 고정하지 않는다. 매 실행마다 현재 목록에서 발견한 수를 보여주고 사용자가
  확인한 뒤에만 상세 저장을 시작한다.
- 수집된 상품은 스마트스토어에 자동 발행되지 않는다.
- 직감 화면 구조가 바뀌어 상품을 찾지 못하면 목록·상세 선택자를 실제 로그인 화면에
  맞춰 갱신해야 한다.

확장 프로그램은 판매 가능, 일부 옵션 품절, 전체 품절, 명시적 단종·판매 종료,
로그인·회원 승인 필요, 판정 불가와 확인 실패를 구분한다. 판정 결과는 확인 문구와
옵션 목록, 확인 시각을 함께 저장하며 스마트스토어 상품을 자동으로 품절 처리하지
않는다.

성장상품 목록의 `직감 전체 확인`은 저장된 직감 상품 URL을 한 탭에서 순차 확인한다.
상품별 결과를 즉시 저장하므로 중간에 중단되어도 완료된 상품은 유지된다. 전체 확인
중에는 Chrome과 Shoppingday 관리 화면을 닫지 않는다. 개별 확인은 기존처럼 상품
상세의 `Chrome으로 품절·단종 확인` 버튼을 사용한다.
