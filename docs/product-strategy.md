# 프로젝트 배경과 핵심 목표

이 문서는 Shoppingday의 제품 방향을 결정하는 기준 문서다. 기능을 설계하거나 구현할
때는 기술적 편의보다 이 문서의 운영 목표를 먼저 고려한다.

## 배경

사용자는 과거 스마트스토어에 약 10,000~20,000개의 상품을 등록하던 대량등록
판매자였다. 당시에는 최대한 많은 상품을 빠르게 등록하고, 그중 일부에서 판매가
발생하도록 만드는 전략으로 전체 매출을 확보할 수 있었다. 따라서 개별 상품의
상품명·키워드·태그를 정교하게 최적화하는 일의 상대적 중요도는 낮았다.

스마트스토어 정책 변경으로 일정 매출 기준을 충족하지 못하면 등록 가능한 상품 수가
약 1,000개로 제한된다. 이제는 상품 수를 무한히 늘리는 전략보다 제한된 슬롯을
효율적으로 사용하고, 판매 가능성이 확인된 상품의 성과를 높이는 전략이 중요하다.

## 핵심 목표

서비스는 다음 두 가지 운영 단계를 명확히 지원해야 한다.

상품 등록 전의 **소싱 조사**는 위 두 단계에 들어가기 전의 의사결정 보조 흐름이다.
키워드 시장, 고객 불편, 리뷰와 품목 위험을 기록해 제한된 상품 슬롯에 넣을 후보를
더 신중하게 고른다. 사용자가 직접 확인한 사실과 판단을 보존하되 특정 체크
조건만으로 재고 소진, 노출 또는 매출을 보장하지 않는다.

### 1. 빠른 등록 단계

- 처음 약 1,000개의 상품을 대량등록 방식으로 빠르게 확보한다.
- AI를 이용해 상품명, 키워드, 태그를 빠르게 괜찮은 수준으로 생성한다.
- 개별 상품에 과도한 분석 시간이나 AI 비용을 사용하지 않는다.
- 완벽한 최적화보다 처리 속도와 안정적인 기본 품질을 우선한다.

### 2. 성장 관리 단계

- 등록 후 실제 판매가 발생하거나 판매 가능성이 보이는 상품만 선별한다.
- 선별한 상품에 키워드 순위 추적, 키워드 변경, 상품명 수정 등의 관리 비용을
  집중한다.
- 키워드 및 상품명 변경 이력을 보존한다.
- 매출과 순위 변화를 함께 비교할 수 있도록 발전시킨다.
- 제한된 상품 슬롯 안에서 성장 상품의 매출을 최대화한다.

## 제품 판단 원칙

모든 기능은 아래 질문을 기준으로 설계한다.

> 이 기능이 1,000개의 제한된 상품 슬롯을 더 효율적으로 운영하고,
> 판매 가능성이 있는 상품의 매출을 높이는 데 도움이 되는가?

이 질문에 직접 도움이 되지 않는 복잡한 기능은 초기 MVP에서 제외한다.

추가 원칙은 다음과 같다.

- 빠른 등록과 성장 관리는 목적과 비용 구조가 다르므로 별도 흐름으로 설계한다.
- 모든 상품에 고비용 AI 분석이나 순위 추적을 자동 적용하지 않는다.
- 판매 반응이 확인된 상품에만 추가 비용과 운영 시간을 집중할 수 있어야 한다.
- AI 추천은 사용자의 판단을 돕는 도구이며, 사실 데이터나 최종 결정을 대신하지 않는다.
- 검색량, 순위, 매출 등은 신뢰할 수 있는 실제 데이터 출처를 사용하고 추정값과
  명확히 구분한다.
- 자동화는 상품 슬롯 효율과 매출 개선 효과가 명확할 때 단계적으로 추가한다.

## 현재 기능 설계에의 적용

- 소싱 조사 기능은 등록 전 후보의 키워드 시장·리뷰·품목 위험 근거를 한곳에 기록하는
  경량 조사 도구다. 검색수와 매출은 사용자가 확인한 값을 입력하며 추정값을 자동
  생성하지 않는다.
- 임시저장한 소싱 아이템은 소싱 조사 목록에만 남는다. 사용자가 등록 초안 생성을
  확정한 항목만 상품 등록관리로 이어지고 이때 소싱 상태를 `소싱 결정`으로 바꾼다.
  등록 준비를 시작하면
  네이버 발행에 필요한 기존 상품 초안 저장 구조를 내부적으로 재사용하되, 소싱 등록
  초안은 일반 상품관리 목록과 편집 흐름에 노출하지 않는다. 사용자는 상품 등록관리의
  전용 편집 페이지에서 상품명·태그·가격, 카테고리·속성·재고·이미지·판매 정책을
  확인한 뒤 발행한다.
- 소싱 등록 초안과 공급사에서 가져온 일반 상품은 화면과 운영 목적을 분리하지만,
  네이버 발행 데이터를 별도 모델에 중복 저장하지 않는다.
- 등록 전용 편집에서 사용자가 상품명·태그·가격을 저장한 뒤에는 그 확정값을 우선한다.
  이후 소싱 조사 메모를 수정해도 등록 편집값을 자동으로 덮어쓰지 않는다.
- 소싱 등록 상품명은 검색수 1,000 이하의 관련 후보 전체를 자동 연결 후보와 자동 연결
  확인 필요 후보로 나눠 보여준다. 사용자는 추천에 사용할 키워드를 여러 개 직접
  선택할 수 있으며, 문자열 자동 연결에 실패했더라도 실제 같은 상품임을 확인한
  후보는 상품명 재료로 사용할 수 있다. 서로 다른 상품형 표현을 50자 안에서 함께
  검토하고 40자 초과부터 즉시 안내하며, 추천 후 실제 반영된 키워드를 보여준다.
- 소싱 등록 검색 태그는 실제 월 검색수를 함께 보여주고 스마트스토어 제한에 맞춰
  최대 10개까지만 선택·저장한다.
- 상품 이미지는 스마트스토어 규격에 맞춰 대표 이미지 1개와 추가 이미지 최대 9개,
  총 10개까지 저장하며 등록 전에 드래그로 노출 순서를 정리할 수 있다.
- 상품명 후보는 검색수 순서대로 단순 나열하지 않는다. 같은 의미의 키워드는 사용자
  선택, 기본 상품 유형과의 연결, 실제 검색수, 구체성 순으로 하나를 고르고 서로 다른
  상품 특징을 우선 조합한다. 관련 후보 전체에서 최우선 키워드를 유지하면서 50자를
  넘지 않는 조합 중 제목 길이를 충분히 활용해 제한된 상품 슬롯의 제목이
  반복적이거나 읽기 어려워지는 것을 막는다.
- 기존 상품 등록 기능은 **빠른 등록 단계**에 해당한다.
- 스마트스토어 링크로 상품을 추가하고 키워드·상품명·변경 이력을 관리하는 기능은
  **성장 관리 단계**에 해당한다.
- 성장 상품에서는 사용자가 같은 검색 조건에서 확인한 실제 키워드 순위를 날짜별로
  기록한다. 자동 추정 순위를 만들지 않고 상품명·태그 변경 전후를 이력으로 비교한다.
- 성장 상품의 판매가·재고·판매 상태·상품명·검색 태그·네이버 공식 카테고리 속성을
  한 화면에서 수정하고 최종 확인 후 기존 스마트스토어 상품에 반영한다.
- 위탁 공급처의 API가 없을 때는 성장상품에 저장한 공급처 URL만 사용자가 요청한
  Chrome 점검 대상으로 삼는다. 상품별 확인과 공급처 전체 순차 확인을 제공하되,
  확인 결과만으로 스마트스토어 판매 상태를 자동 변경하지 않는다.
- 최근 7일·30일 판매량은 네이버 주문 API의 결제일과 취소·반품 후 잔여수량을 기준으로
  사용자가 새로고침할 때 집계한다. 조회하지 않은 값을 0이나 추정값으로 표시하지
  않는다.
- 초기 키워드 관리 MVP는 상품 연결, 규칙 기반 상품 분석, 네이버 연관 키워드와 실제
  검색량 확인, 사용자 키워드 선택, 상품명 초안 편집 및 결과 저장에 집중한다.
- 성장 상품 키워드 관리는 외부 생성형 AI 선택 경로 없이 규칙 기반 기본 모드로
  동작한다. 검색량과 경쟁도는 네이버 검색광고 API의 실제 응답만 사용한다.
- 성장 상품의 인기도를 검토할 때는 스마트스토어 공식 SEO 가이드(2025년 3월판)가
  설명하는 최근 1개월의 클릭·리뷰·판매·최신성 범위를 우선 비교하되 실제로 확보한
  값만 사용한다.
  인기도를 다시 얻기 위한 상품 삭제·재등록 반복은 운영 전략으로 사용하지 않는다.

## 문서 유지 원칙

제품의 핵심 운영 전략이 바뀌면 이 문서를 먼저 갱신하고, 그 변화가 라우팅, 데이터
모델, 비용 정책, 외부 API 사용 범위에 미치는 영향을 함께 검토한다. 세부 구현 문서는
이 문서와 충돌해서는 안 된다.
