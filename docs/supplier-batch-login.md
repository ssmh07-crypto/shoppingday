# 선택 도매처 통합 실행 및 PC 로그인 보관함

## 사용 방법

1. Chrome 확장 프로그램 관리에서 Shoppingday를 다시 로드해 0.5.20으로 갱신하고 웹페이지를 새로고침한다.
2. 위탁상품 가져오기에서 `PC 로그인 보관함`을 연다.
3. 12자 이상의 별도 보관함 암호를 만들고 직감·이불삼촌의 아이디/비밀번호를 저장한다.
4. 확인할 도매처를 선택하고 통합 실행 버튼을 누른다. 마지막 선택과 순서를 이 브라우저에 기억한다.
5. 실패한 도매처는 결과를 확인한 뒤 실패 항목만 다시 실행한다.

친구도매는 기존 서버 API 인증 설정을 사용한다. 직감·이불삼촌은 Chrome과 가져오기 화면을 열어 두어야 한다.
통합 실행은 도매처별 수집과 DB 저장을 순서대로 기다린다. 이미 시작된 서버 저장 작업은 중단 버튼으로 취소되지 않는다.
이 작업의 완료는 공급처 정보 수집/저장 완료이며 스마트스토어 반영 완료가 아니다.
통합 실행의 평소 변경 확인은 스마트스토어 등록 상품만 대상으로 한다. 직감·이불삼촌은
등록 상품 상세주소만 열며 전체상품 목록은 각 도매처 카드의 초기 연결·누락 복구 도구를
직접 선택했을 때만 확인한다.

## 보안과 제한

- 아이디와 비밀번호는 AES-GCM으로 암호화해 확장 프로그램의 로컬 저장소에만 보관한다.
- 보관함 암호로 PBKDF2-SHA256(600,000회) 키를 유도한다. 잠금 해제 키만 확장 프로그램 세션 메모리에 둔다.
- Chrome 재시작·확장 다시 로드 후 잠금을 다시 해제해야 한다. 암호를 잊으면 보관함을 초기화하고 계정을 다시 입력한다.
- Shoppingday 웹페이지/서버로 로그인 비밀번호를 전달하지 않는다. 승인된 수집 탭의 도매처 로그인 양식에만 전달한다.
- CAPTCHA, 추가 인증, 변경된 로그인 양식은 자동 우회하지 않는다. 직접 로그인하고 재시도한다.
- 저장소 접근 제한과 세션 수명은 [Chrome storage 공식 문서](https://developer.chrome.com/docs/extensions/reference/api/storage)를 따른다.

## 검증 범위와 남은 작업

암호화·잠금·잘못된 암호 거부 및 기존 확장 브리지 회귀 테스트를 추가/실행했다.
실계정 로그인과 실제 도매처 일괄 수집은 사용자 Chrome에서 확인해야 한다. 도매처 로그인 DOM 변경 시 수동 로그인으로 복구한다.
공급가 변경 시 판매가 재계산과 스마트스토어 가격 반영/재시도는 후속 구현했다. 현재 적용·검증 상태와 남은 작업은 `implementation-progress-2026-09-08.md`를 따른다.
