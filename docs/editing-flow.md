# 상품 편집 흐름

1. 공급사 상품을 가져오면 원본은 `supplier_products`에 저장하고 판매 초안은 `products`에 한 번 생성한다.
2. 목록과 편집 화면은 DB만 조회한다. 친구도매 API를 호출하지 않는다.
3. 사용자는 원본 읽기 전용 영역을 참고해 판매 필드를 편집한다.
4. 임시저장은 Zod 검증, HTML 정화, `draft_version` 충돌 검사, 조건부 업데이트, 감사 로그 기록 순서로 수행한다.
5. 등록 준비 완료는 필수값을 검사해 내부 상태만 `ready`로 바꾼다.
6. ready의 중요 필드를 다시 저장하면 `editing`으로 돌아간다.
7. 이미지/옵션 원본 초기화는 확인 후 명시적으로만 수행한다.
8. 등록 전 검사와 사용자의 확인 후 `product_publications`와 네이버 발행 서비스를 통해 스마트스토어에 실제 등록·수정한다. 내부 준비 상태와 외부 등록 상태는 별도다.

## 2026-09-08 작업 경로

- 위탁판매: `/admin/products/import`에서 수집·변경 확인 → `/admin/products`에서 선택·키워드 가공·등록.
  선택은 현재 검색 조건·페이지에 한정하며 준비 완료 상품을 한 번에 선택할 수 있다.
- 사입판매: `/admin/sourcing`에서 조사 → `/admin/registration`에서 초안 준비 → 전용 편집기에서 등록.
  과거 `/admin/registration?tab=wholesale` 링크는 위탁상품관리로 이동한다.
- 성장관리: 등록된 위탁상품의 `성장관리` 버튼으로 현재 발행 대상 스토어의 상품을 연결한다.
  이미 연결된 상품은 기존 기록을 열고, 링크된 내부 상품과 네이버 상품번호를 보존한다.
- 공급처 예약: 친구도매만 6·12·24시간 주기 설정을 저장한다. 기본은 해제이며 스케줄 실행기는
  매시간 기한이 지난 예약을 확인한다. 설정 시각 이후 첫 실행도 지정 간격을 기다린다.
  GitHub Actions 대기나 장애로 실행이 지연될 수 있다. 예약은 공급처 변경 수집이며
  스마트스토어 자동 가격·판매 상태 변경은 아직 포함하지 않는다.

자동저장은 구현하지 않았다. 입력 변경 시 상단에 미저장 상태가 표시되고, 페이지 이탈 시 브라우저 경고가 나오며, 수동 임시저장 결과와 시간이 표시된다.
