# Shoppingday 최적화 측정 기록 (2026-08-14)

## 우선순위

1. 소싱 조사에서 상품 등록 편집까지의 반복 작업 단축
2. 소싱 등록 초안과 기존 위탁상품 사이의 중복 데이터 제거
3. 일반 위탁상품 편집기의 키워드 작업 통합
4. 기존 동작과 초기 로딩 비용 유지

## 변경 전 기준

- 프로덕션 빌드: 23.326초
- 상품관리 페이지 초기 클라이언트 청크: raw 28 KiB, gzip 9 KiB
- 가장 큰 지연 로딩 청크: raw 83 KiB, gzip 24 KiB
- `ProductEditor`: 3,490줄, 약 142.9 KB
- 소싱 등록에서 직감 원본 선택: 이미지 탭으로 이동한 뒤 검색
- 직감 원본 적용: 소싱 초안과 직감 상품을 별도 상품 행으로 유지하며 콘텐츠 복사

## 적용 결과

- 직감 원본 선택기를 기본정보 첫 화면으로 이동하고 소싱 키워드를 검색어로 미리 채웠다.
- 직감 원본을 선택하면 소싱 확정 정보는 기존 직감 상품에 적용하고, 조사 연결도 같은
  상품 ID로 옮긴 뒤 임시 소싱 상품과 임시 공급처 데이터를 제거한다.
- 아이템스카우트 엑셀 후보와 분류 상태를 상품에 한 번 저장해 재업로드·재분류를 줄였다.
- 엑셀 파서는 파일을 선택할 때만 내려받는 지연 로딩 경로로 유지했다.
- 키워드 작업공간, 검색 최적화 요약, 직감 원본 선택기를 편집기 본체에서 분리했다.
- 상품 목록의 초기 클라이언트 청크는 raw 28 KiB, gzip 9 KiB로 유지됐다.
- 프로덕션 빌드는 23.208초로 기준과 같은 수준이다.
- 가장 큰 지연 로딩 청크는 새 키워드 기능을 포함해 raw 86 KiB, gzip 25 KiB다.
- `ProductEditor` 본체는 3,472줄이며 새 기능 UI는 별도 지연 로딩 컴포넌트에 배치했다.
