## 이번 코드 변경

- 위탁상품 목록의 모든 상품을 미등록으로 세던 임시 구현을 제거했다. 원상품번호가 있고
  삭제되지 않은 발행 연결이 있는 상품을 등록됨으로 표시한다. 후속 수정 실패만으로
  등록됨을 미등록으로 바꾸지 않는다. 여러 스토어에 등록해도 상품 수를 중복 계산하지 않는다.
- 공급 상태 `unknown`을 판매 가능으로 집계하지 않는다. 목록은 기본 공급처 연결만
  조회하고 같은 정렬값에는 상품 ID 정렬을 추가해 페이지 순서를 안정화한다.
- 일괄 작업은 선택한 상품만 받는다. 생성 중 중복 클릭을 막고 이전 진행 작업 복구,
  통신 실패 안내, 화면 이탈 시 후속 요청 중지와 수동 재개를 제공한다.
- 메뉴를 위탁판매·성장관리·사입판매·운영 도구로 구분한다. 상품번호 설정은 접어두고
  목록 선택과 처리 버튼을 작업 영역에 배치한다. 상품 이미지에 지연 로딩을 적용했다.
- 상품등록관리에서 위탁 목록과 전용 중복 조회 저장소를 제거했다. 원본 상품·발행 데이터는
  삭제하지 않았다. 위탁상품 편집기의 기존 네이버 등록·수정·판매 상태 변경 기능은 유지한다.
- 상품 목록에서 친구도매만 실행하던 일반적인 이름의 변동처리 버튼을 공급처별 수집 화면
  링크로 바꿨다. 공급처 상태 조회는 실행 중 5초, 대기 시 60초이며 숨긴 탭에서는 멈춘다.
- 무거운 관리 페이지의 메뉴 사전 불러오기를 끄고 페이지 이동 중 로딩 안내를 추가했다.

## 예약 구현과 적용 순서

1. `0031_luxuriant_morgan_stark.sql` 마이그레이션으로 예약 테이블과 소유자 RLS를 적용한다.
2. 앱과 `product-sync.yml`을 배포한다. 순서를 반대로 하면 예약 조회가 실패할 수 있다.
3. 예약은 기본 해제다. 친구도매 카드에서 주기를 선택해 저장한 뒤 활성화한 설정을 확인한다.
4. 스케줄 실행은 기존 동기화와 같은 concurrency 그룹을 쓰며 행 잠금으로 예약을 선점한다.
   실행 직전에 설정 소유자의 관리자 역할을 확인하고 사용자의 판매 필드 보호 설정을 읽는다.
5. 공급처별 예약은 하나다. 다른 관리자가 만든 예약을 덮어쓰지 않는다. 예약 실패는 기존
   동기화 작업 상태와 Actions 로그에서 확인한다. 실패 후 다음 주기에 다시 변경 구간을 조회한다.
6. 예약 수집과 스마트스토어 반영은 다르다. 현재 예약은 외부 판매 상태·판매가를 자동 변경하지 않는다.

## 후속 구현 우선순위

1. 공급처 변경 이력·검토 대기열: 품절·공급가·상세페이지·단종 근거를 보존하고 상품별 적용 항목을 표시.
2. 가격 정책 확정: 기존 마진율 유지 / 알림만 / 상품별 마진 규칙 중 사용자의 선택을 반영.
   정책이 정해지기 전에는 공급가 변동으로 판매가를 자동 계산하지 않는다.
3. 엑셀 가공 일괄 적용: 상품군별 후보 재사용, 변경 미리보기, 버전 충돌 검사와 부분 실패 복구.
4. 성장상품 정밀 분석 공통화: 소싱의 분석 기능을 재사용하되 위탁 빠른 등록에 분석 비용을 강제하지 않음.
5. 변경 적용 실행기: 사용자 정책에 따라 등록된 상품만 순차 수정하고 동일 요청 중복 반영 방지.
6. 실제 브라우저에서 데스크톱·좁은 화면의 작업 흐름과 미저장 상태·키보드 조작·배치 검수.

## 유료 구성 추천

2026-09-08 공식 공개 가격 확인 기준이며 세금·추가 사용량은 별도다. 실제 계정 청구 상태는 조회하지 않았다.

- **우선 검토: Cloudflare Workers Paid, 월 $5부터.** 현재 Next.js/OpenNext 운영에서 무료의
  요청당 CPU 제약을 완화하는 용도로 추천한다. DB 쿼리 지연, 네이버 제한, 로그인 Chrome
  의존성이 함께 해결되는 것은 아니다. [Workers 가격](https://developers.cloudflare.com/workers/platform/pricing/),
  [실행 한도](https://developers.cloudflare.com/workers/platform/limits/).
- **운영 데이터가 중요해지면: Supabase Pro, 월 $25부터.** DB·인증·Storage를 이미 쓰므로
  서비스 이전 비용 없이 유료 운영 기능을 확보할 수 있다. 실제 DB 용량·사용량·백업 필요를
  확인해 결정한다. 기본 두 플랜 합계는 월 $30부터이며 추가 프로젝트·컴퓨트·초과 사용량에
  따라 달라진다. [공식 가격](https://supabase.com/pricing),
  [비용 관리](https://supabase.com/docs/guides/platform/cost-control).
- 로컬 네이버 릴레이와 Quick Tunnel은 비용보다 PC 가동·재연결에 따른 운영 의존성이 있다.
  등록 후 자동 반영을 상시 운영할 때 고정 출구 IP를 가진 상시 서버를 별도로 비교한다.
  구체 사업자·가격은 선택 시 조사하고 이번에 구매하지 않는다.
- GitHub Actions는 먼저 실제 실행 분량을 확인한다. 시간별 예약 검사에도 설치 시간이 들므로
  워크플로 캐시·빈 예약 실행 비용을 측정한 뒤 필요할 때 요금제를 검토한다.
